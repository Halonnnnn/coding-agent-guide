# 4.12 搜得到与讲得清【基准】

随着 Agent 工具逐渐成熟，判断一个工具能否写好代码，要看两个层面。在模型能力足够的前提下，**工具能让模型检索到什么信息，比模型能凭空创造出什么优秀代码更重要**，概括起来就是“搜得到”和“讲得清”：

- **搜得到**：按需找到具体那段代码。不仅依赖 grep 的字符串匹配，还要有语义检索能力——根据上下文语义搜索代码，如 Cursor 的 Codebase Indexing、Qoder 的代码检索。它贯穿 Agent 的工作全程：规划阶段用它定位改动范围，执行阶段用它找到具体实现。
- **讲得清**：是否懂得项目的业务与架构约定。前者如业务领域知识，后者如模块分层、依赖方向、设计决策。载体可以是 Qoder 的 Repo Wiki，也可以是自建的业务本体（对应 [2.2](../02-核心问题/2.2-需求映射与项目知识.md) 的服务地图与 [4.3](4.03-项目知识分三层管理.md) 的项目知识分层）。

注意：

**“搜得到”不等于“必须有语义向量索引”。** Claude Code 团队提到，早期试过 RAG + 本地向量库，最终发现模型驱动的 grep/glob 迭代检索“全面胜出”，理由收敛为四点：准确、永远新鲜、无索引副本的隐私负债、组件少更可靠。检索方式应当以实际效果选择，而不是默认上向量索引。

**两者缺一不可**：缺了“搜得到”，Agent 找代码慢、容易找漏；缺了“讲得清”，Agent 找得到代码，但可能改错地方、破坏设计。
