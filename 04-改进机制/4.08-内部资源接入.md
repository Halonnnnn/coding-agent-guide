# 4.8 内部资源接入【需基础设施】

内部资源接入解决的是信息本身不可访问的问题，而不是信息如何组织的问题。接入应当围绕实际任务来设计，优先覆盖最影响定位效率的高频信息源，例如日志、部署记录、需求文档和历史工单。

- **优先提供只读查询**：按关键词查询授权范围内的文档，按时间和服务名查询日志，查询指定环境和版本的部署记录、工作负载状态和事件。
- **写入操作需要单独设计**：对于生产环境，重启、发布等会改变系统状态的操作，应当有独立的审批流程、权限隔离和审计机制。不能因为 Agent 能调用工具就直接授予相应的写权限。
- **跨系统关联才有价值**：以“本地正常、部署后异常”为例，排查时通常需要依次确认：当前环境部署的是哪个版本、异常时间与部署时间是否相关、对应服务是否有错误日志和异常事件、相关接口或配置是否发生变化、异常是否与历史问题或最近的修改有关。无法获取的信息，Agent 应当明确说明缺口，而不是用推测来填补。
- **遵循最小权限原则**：只开放任务所需的系统和数据范围，限制大范围扫描，过滤敏感信息，记录关键工具的调用日志。

MCP（Model Context Protocol）可以作为连接 Agent 与内部工具的标准化机制，但它本身不会自动赋予访问权限。每个系统仍然需要完成接口实现、身份认证、权限配置、参数校验和结果处理。
