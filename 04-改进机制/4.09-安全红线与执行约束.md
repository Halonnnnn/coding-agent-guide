# 4.9 安全红线与执行约束【需基础设施】

安全红线不能只依赖用户提示词。像 `rm -rf /`、未经授权读取私钥、Token 和密码等操作，如果只写在用户提示词中，可能随着上下文增长而被模型忽略。即使将规则写入 System Prompt、AGENTS.md、CLAUDE.md 等高优先级配置，也无法保证模型百分之百遵守。

因此，安全红线应同时写入高优先级规则配置，并通过程序化机制进行强制约束，不能单纯依赖模型对指令的遵守。

具体可以从五个层面进行防护：

1. 系统规则层：将安全规则写入 System Prompt、AGENTS.md、CLAUDE.md 等配置文件，明确告诉 Agent 哪些操作禁止执行。
2. Hook 拦截层：优先使用 PreToolUse 一类的 Hook，在工具执行前检查并拦截危险操作，将安全规则转化为程序化约束。
3. 权限隔离层：通过 Sandbox、文件系统权限、命令白名单等机制，限制 Agent 实际能够访问和操作的资源范围。
4. 凭证保护层：对私钥、Token、密码等敏感信息进行隔离和访问控制，禁止未经授权读取，并避免通过环境变量、日志或工具输出泄露。
5. 审计监控层：记录工具调用和执行结果，对异常操作及敏感信息泄露进行检测和告警，便于追踪和排查问题。

这五个层面的职责可以概括为：

* Prompt：告诉 Agent 什么不能做。
* Hook：在执行前拦截不允许的操作。
* Sandbox：从权限和执行环境层面限制 Agent 的实际能力。
* Secret Protection：保护敏感凭证，减少不必要的访问。
* Audit：发现、记录和追踪异常行为。

需要注意的是，这些机制并非相互替代，而是构成纵深防御体系。Prompt 负责行为引导，Hook 负责执行拦截，Sandbox 和权限控制提供更底层的安全边界，凭证保护降低敏感信息暴露风险，审计监控负责发现和追踪问题。

核心原则：不要把安全寄托在模型是否遵守指令上，而要尽可能将安全红线转化为模型无法轻易绕过的执行约束。
